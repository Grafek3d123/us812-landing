# HERO-TUNING — затемнение и читаемость mobile hero

Документ про **одну конкретную вещь**: как сделать фоновую печатку в мобильном
hero различимой и не уронить при этом читаемость текста. Правится двумя
ручками в `css/style.css`; здесь — где они, какие пределы и как мерить.

Кому это нужно: когда в очередной раз захочется «чуть осветлить фон» или
когда после смены фото/оверлея hero начнёт «плыть».

---

## 1. Механизм: два независимых рычага

Оба лежат в одном блоке `@media (max-width: 767px)` в `css/style.css`
(ориентир — строки ~331–348, ищите по селектору `.hero__bg::after`).

| # | Ручка | Селектор | Текущее значение | Что делает |
|---|-------|----------|------------------|------------|
| 1 | **Overlay** | `.hero__bg::after` → `linear-gradient(...)` | `rgba(10,10,10, 0.84 / 0.78 / 0.84)` | Прозрачность тёмной вуали поверх фото. Меньше число → светлее и сильнее виден фон |
| 2 | **Brightness** | `.hero__bg img` → `filter` | `brightness(1.18)` | Осветляет саму фотографию до вуали. Больше число → светлее фон |

Структура слоёв (снизу вверх): фото `.hero__bg img` → вуаль `.hero__bg::after`
→ контент `.hero__content`.

Рычаги **перемножаются**: каждый даёт ~+18% яркости, вместе — ~+45%. Поэтому
осветлять ими одновременно — это сразу два шага, а не один.

### ⚠️ Ловушка, из-за которой правка может обнулиться

`filter` вешать **только на `.hero__bg img`**, ни в коем случае не на `.hero__bg`.
Псевдоэлемент `::after` наследует фильтр родителя: повесите на контейнер —
осветлится и вуаль, то есть и фон, и затемнение одновременно. Визуально —
почти без изменений, при этом цифры замеров поедут. Это главная причина,
по которой сюда вообще нужен документ.

### Desktop — отдельно и туда не лезть

Desktop-оверлей определён базовым правилом `.hero__bg::after` (строки ~320–329):
`linear-gradient(135deg, ...0.92 / 0.85 / 0.92)`. Мобильные ручки на него не
влияют. Если менять нужно и desktop — менять базовое правило **отдельно** и
мерить `--widths 1280 1440 1920` (для него пороги AA свои).

## 2. Как мерить (обязательно цифрами, не глазами)

```powershell
pip install playwright pillow numpy      # один раз

python tools/hero_metrics.py                     # текущее состояние
python tools/hero_metrics.py --baseline --new    # сравнить с прежними значениями
python tools/hero_metrics.py --widths 375 390    # нужные ширины
```

Скрипт открывает локальный `index.html` в Chrome, снимает скриншот секции
`#hero` и считает **по реальным пикселям**, а не по цвету из CSS:

| Колонка | Смысл | Куда смотреть |
|---------|-------|---------------|
| `bgMean` | средняя яркость фона, 0–255 | «насколько вообще светло» |
| `bgStd` | разброс яркости внутри фона | **главный показатель: растёт = печатка различима** |
| `h1`, `price`, `subtitle`, `geo` | контраст текста с фоном под ним: `worst/median` | не ниже **4.5:1** (WCAG AA) |

`worst` — самый светлый пиксель фона под текстом (пессимистичная оценка),
`median` — типичный. Ориентироваться на `worst`.

`--baseline` подменяет прежние значения оверлея инъекцией CSS в браузере —
**файлы и git не трогаются**, откат не нужен.

Метрику скрипт не трогает (`window.ym` подменяется заглушкой), тестовые
pageview в счётчик не утекают.

## 3. Безопасные пределы

Самый чувствительный элемент — **не H1, а золото цены** (`.hero__price strong`,
`#c9a84c`) и **`.hero__geo`**: они темнее белого текста, поэтому первыми
начинают тонуть при осветлении фона.

| Ориентир | Значение |
|----------|----------|
| Критический порог | любой из четырёх контрастов < **4.5:1** → осветление слишком сильное |
| Текущий худший (320px, `geo`) | **5.08:1** — запас до порога небольшой |
| Практический вывод | дальше осветлять только `bgStd`-методом и **с перезамером** |

Комментарий в CSS («белый текст >10:1, золото цены >6:1») — производный от
этих замеров; если меняете ручки, обновляйте и его.

## 4. Опорные числа (13.09.2026, задача Task02)

Состояние «фон почти чёрный, печатка не читается» → состояние «печатка
узнаваема». Мобильные ширины, `bgMean`/`bgStd` — из `--baseline --new`:

| Ширина | До: bgMean / bgStd | После: bgMean / bgStd | Худший контраст: до → после |
|--------|--------------------|-----------------------|------------------------------|
| 320 | 17.3 / 9.0 | 22.3 / **15.0** | 4.18 → **5.08** |
| 375 | 18.8 / 9.2 | 26.9 / **16.6** | 4.39 → **5.08** |
| 390 | 18.7 / 9.0 | 27.3 / **16.2** | 5.56 → 5.08 |
| 430 | 18.8 / 8.8 | 27.8 / **15.9** | 5.06 → 5.08 |
| 1280 (desktop) | 21.3 / 9.9 | 21.3 / 9.9 — **без изменений** | — |

Два факта, которые стоит помнить:

1. **`bgStd` вырос сильнее, чем `bgMean`** (+67…81% против +29…48%). Именно
   разброс, а не средняя яркость, отвечает за «видно, что на фоне печатка».
   Фон остался очень тёмным (27 из 255), но изделие в нём читается.
2. **До правки на 320px контраст `.hero__geo` был 4.18:1 — ниже WCAG AA.**
   То есть старый, более тёмный вариант сам по себе нарушал норму контраста
   для этого текста; текущий вариант (5.08:1) эту проблему закрыл.

Desktop подтверждён как неизменный: скриншот hero 1280×900 в обоих режимах
байт-в-байт идентичен.

## 5. Рецепты

**Стать светлее (аккуратно, один шаг):**
`.hero__bg img` → `brightness(1.24)`, overlay не трогать. Перезамерить.

**Откатить на полшага назад (фон всё ещё светел):**
```css
.hero__bg img  { filter: brightness(1.12); }
.hero__bg::after {
    background: linear-gradient(180deg,
        rgba(10,10,10,0.88) 0%, rgba(10,10,10,0.82) 45%, rgba(10,10,10,0.88) 100%);
}
```

**Полный откат к «почти чёрному фону»:** значения из константы
`BASELINE_MOBILE_CSS` в `tools/hero_metrics.py` (0.95/0.88/0.95, `filter: none`).
Не рекомендуется: см. пункт 4.2 про нарушение контраста.

**Меняется фото hero** (`assets/images/ring-1.jpg`) → светимость фона
поменяется сама. Обязательно `python tools/hero_metrics.py` и, возможно,
уменьшить `brightness`.

---

## 6. Чего здесь делать НЕ нужно

- Компенсировать осветление фона жирностью/размером шрифта или правкой текстов —
  только яркость и вуаль.
- Трогать `min-height`/padding hero — это другая задача (там решалась высота
  первого экрана и попадание CTA в фолд).
- Осветлять desktop «заодно» — у него свои значения и свои замеры.
- Заменять `filter` на `opacity` картинки — `opacity` покажет под фото тело
  страницы, а не осветлит его.
